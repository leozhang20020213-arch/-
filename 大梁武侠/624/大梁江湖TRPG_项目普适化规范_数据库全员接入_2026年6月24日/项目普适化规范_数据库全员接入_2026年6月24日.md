不要再把数据库当“Excel参考资料”。从这一轮开始，数据库必须成为项目的 **单一条目源**。规则书负责解释玩法；数据库负责保存可调用条目；App负责记录、校验、展示和回放。

## 1. 项目普适化总原则

### 1.1 三层分工

项目分为三层，不允许混在一起：

1. **规则解释层**：玩家规则书、DM规则书、术语表。只解释规则，不负责承载全部条目。
2. **数据库条目层**：招式、响应、武器、状态、内功、药物、敌人、动景等。所有可调用条目必须在这里。
3. **App运行层**：角色卡、交锋流程、气骰、状态、场景轨、日志、检索与校验。App不得接管自由叙事、玩家推理和NPC自然语言。

### 1.2 不允许再写死条目

禁止：

```ts
const moves = [WG001, WG002, WG003]
```

必须：

```ts
const moves = db.moves.getAll()
const reactions = db.reactions.getByMoveId(moveId)
const statuses = db.statuses.getAll()
```

所有UI、角色创建、DM工具、交锋引擎、日志回放都应通过统一DataRegistry读取，不得在组件里手写少量样例数据。

### 1.3 全表必须有入口

“全员接入”最低标准：

- 每张表能在数据库浏览器中被看见；
- 每条记录能通过ID打开详情；
- 每张表能被搜索、筛选；
- 每条规则对象能被至少一个业务模块引用；
- 所有关联ID可反查；
- 数据错误会被校验器指出，而不是静默失败。

## 3. 统一数据类型

## 4. 统一Registry

```ts
export interface DatabaseRegistry {
  moves: DbCollection<MoveEntry>
  reactions: DbCollection<ReactionMount>
  weapons: DbCollection<WeaponEntry>
  gearTools: DbCollection<GearToolEntry>
  statuses: DbCollection<StatusEntry>
  medicines: DbCollection<MedicineEntry>
  sceneElements: DbCollection<SceneElementEntry>
  enemies: DbCollection<EnemyTemplate>
  innerArts: DbCollection<InnerArtEntry>
  documentsManuals: DbCollection<DocumentManualEntry>
  mountsVehicles: DbCollection<MountVehicleEntry>
  materialsRelics: DbCollection<MaterialRelicEntry>
  validationRules: DbCollection<ValidationRule>
  termMappings: DbCollection<TermMapping>
}

export interface DbCollection<T extends BaseDbEntry> {
  key: DatabaseTableKey
  label: string
  rows: T[]
  getAll(): T[]
  getById(id: string): T | undefined
  search(keyword: string): T[]
  filter(predicate: (row: T) => boolean): T[]
}
```

必须新增 `getDatabaseRegistry()`，由全项目统一调用。

## 5. 数据导入顺序

优先使用 ZIP 里的 JSON/CSV；不要让前端运行时解析Excel。Excel用于人工查看，项目运行数据使用生成后的JSON。

顺序：

1. 把 `大梁江湖TRPG_数据库扩充包_第二批合并版_2026年6月24日.xlsx` 放到 `data/daliang/raw/`；
2. 若 ZIP 内已有 JSON/CSV，直接复制到 `data/daliang/generated/`；
3. 若没有 JSON，写脚本从 xlsx 导出 JSON；
4. 每张表生成独立 JSON；
5. 生成 `database_manifest.json`，记录表名、数量、字段、版本；
6. 导入前跑校验器；
7. 校验通过后再接入 UI 和规则引擎。

## 6. 校验规则

### 6.1 通用校验

每张表必须检查：

- ID不能为空；
- ID全局或表内唯一；
- 名称不能为空；
- 旧口径字段不得出现：命中、命中槽、夺势、上一招前置、独立响应池；
- 所有效果必须能落到：气血、状态、气骰区域、势、危机值、解密值、资源、关系事实、目标线、装备状态；
- 资源去向不得为空。

### 6.2 招式校验

- 低级招式通常应为无势/宽势；
- 强招、绝式、强截击、强应招应有中势或单势限制；
- 硬前置默认必须为“无”；
- `挂载截击=是` 时，响应挂载表必须能按招式ID反查到至少一条截击；
- `挂载应招=是` 时，响应挂载表必须能按招式ID反查到至少一条应招；
- 差值/风险必须是明确落果，不得写“可能”“大概”“气机不稳”这种空泛表述。

### 6.3 响应校验

- 响应必须绑定有效招式ID；
- 响应类型只能是截击或应招；
- 截击时点必须在宣言后、成招前；
- 应招时点必须在成招后、落果前；
- 响应必须有自己的最低投入、势条件、效果和资源去向；
- 响应调用不得自动获得主用法基础效果。

### 6.4 状态校验

状态必须具备四件套：

1. 名称；
2. 层数/强度；
3. 规则效果；
4. 衰减方式或解除入口。

缺任一项，不允许进入正式运行。

### 6.5 装备/药物/器具校验

- 必须记录来源；
- 如提供气骰，必须写清气性、骰阶、数量、常规/临时；
- 来源失效时能被移除或重新校验；
- 不允许“装备给一个加成”但不说明落点。

## 7. 业务模块接入要求

### 7.1 数据库浏览器

新增一个通用数据库浏览器页面，至少包含：

- 左侧表分类；
- 顶部全局搜索；
- 层级、类型、势条件、投放层筛选；
- 中间列表；
- 右侧详情；
- 关联反查：招式 → 响应挂载；武器 → 可挂载招式；状态 → 常见来源；敌人 → 动作/响应/掉落。

### 7.2 玩家角色卡

接入：

- 内功库：选择内功、占窍、读取六根、表属性运算、取气运算；
- 招式主表：玩家武艺栏；
- 响应挂载：自动显示可用截击/应招；
- 武器/护具器具：装备栏与装备许可；
- 药物资源：背包与取物；
- 状态库：状态栏。

### 7.3 DM控制台

接入：

- 敌人模板；
- 动景库；
- 药物/装备/文书/材料投放；
- 危机值、解密值、目标线；
- 敌人简化气骰；
- 阶段机制和掉落资源。

### 7.4 交锋引擎

交锋引擎不能只显示卡片，必须读数据库字段：

- 宣言时读取：时点、对象、距离、装备许可、最低投入、气性门槛、势条件；
- 截击窗口读取：响应挂载表中响应类型=截击；
- 成招后读取：基础效果、主槽触发、合值触发、差值风险；
- 应招窗口读取：响应挂载表中响应类型=应招；
- 落果时写入：气血、状态、势、气骰去向、目标线、危机/解密、装备状态、日志。

### 7.5 日志系统

每条日志必须记录：

```ts
{
  time: string,
  sceneId: string,
  actorId: string,
  targetIds: string[],
  sourceTable: DatabaseTableKey,
  sourceId: string,
  actionType: string,
  diceBefore: QiDieSnapshot[],
  diceAfter: QiDieSnapshot[],
  effects: ResolvedEffect[],
  manualOverride?: string
}
```

手动修正必须写入日志，不允许无痕改结果。

## 9. 最终验收标准

完成后必须满足：

1. 数据库14张核心表全部接入；
2. 数据库浏览器能看到所有表；
3. 任意ID可打开详情；
4. 招式能反查响应挂载；
5. 响应不能脱离招式单独乱用；
6. 武器/护具/器具能影响装备许可；
7. 药物/装备/状态给出的气骰都有来源；
8. 来源失效可触发重新校验；
9. 敌人模板能进入DM控制台；
10. 动景能进入场景轨；
11. 内功能进入角色创建和内功盘；
12. 文书谱本、坐骑载具、材料奇物不再只是库存文字，而能作为资源/投放/关系事实入口；
13. 删除旧链式前置、命中槽、夺势等旧口径；
14. 每阶段均有 README；
15. 远端Git有提交记录。

## 10. 禁止事项

- 禁止只接入招式和武器，忽略状态、动景、敌人、内功等表；
- 禁止把响应挂载做成独立大招池；
- 禁止让截击自动继承主用法伤害；
- 禁止在UI组件里继续写死少量样例；
- 禁止旧字段复活：命中、命中槽、夺势、固定链式前置；
- 禁止状态只有描述没有层数/衰减/解除；
- 禁止装备/药物给骰但不记录来源；
- 禁止导入失败后静默跳过；
- 禁止没有README就进入下一阶段。
