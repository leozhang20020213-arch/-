# 大梁江湖 TRPG 交锋系统重构 R7 设计基线

## 1. 本轮目标

本轮不是换皮，而是对现有 React 游戏原型的交锋主屏、气骰资源、宣言草稿、响应时点、玩家/DM 分工和事件反馈做一次结构与功能的整体重构。

产品定位保持为“大梁江湖 TRPG 专用交锋辅助桌面”，不扩张为通用 VTT，不代替自由叙事、NPC 话术、玩家推理与江湖判断。

## 2. 优先级与冲突裁决

优先级从高到低：

1. `玩家规则书_内测第一版_修复版`、`DM规则书_内测第一版_修复版`、`开发者规则书_交锋辅助引擎_修复版`。
2. 2026-06-24 至 2026-06-26 的 React 交锋重构日志与代码。
3. R6、PHASE2/PHASE3、游玩交互设计、UI 设计规范等历史设计文档。

历史冲突的统一口径：

- R6 早期的“气骰五区摘要”被规则书修复版更新为气骰七区：气池、气海、锁气、阴槽、阳槽、息库、临气区。
- 禁止逐点点击，但允许以“整枚气骰”为单位拖拽或键盘分配到阴阳槽。
- 宣言以“选卡 → 选目标 → 配气骰 → 单一确认”为主路径；双击可作快捷操作，不取消可发现、可无障碍的确认入口。
- 阶段不做平铺的开发者流程按钮墙；底部只呈现当前时点的唯一主操作与理由。
- 调息、返照、取物、争夺物、便行是行动卡/操作卡，不做长驻裸按钮。

## 3. 交锋主循环

```text
准备交锋
→ 确认参战对象、动景、目标线、状态、装备与初始势
→ 按表属性 + 最高可用气骰 + 状态修正得到先后
→ 新场景中将气池常规气骰整体 3D 投掷入气海
→ 选择行动卡/招式卡
→ 选择目标，建立“行动方 → 承受方”目标线
→ 从气海/临气区选整枚气骰，分配阴槽和阳槽
→ 校验对象、距离、装备许可、时点、最低投入与明示势条件
→ 确认宣言，气骰进入锁气
→ 开截击窗口；截击只干预成招条件
→ 成招，结算基础效果与阴值/阳值/合值/阴阳差触发
→ 开应招窗口；应招只处理已成招、未落果的结果
→ 落果，写入气血、状态、势、位置/目标线、场景轨与资源去向
→ 常规已用骰入息库，临时骰按条目消失
→ 下一行动者 / 轮次结束检查
```

## 4. 界面区块

### 顶部交锋栏

- 场景、轮次、当前时点。
- 按先后值排序的行动队列，区分已行动、当前、待行动、可响应。
- 顶栏不重复显示“当前角色徽章 + 当前行动芯片”。

### 左侧状态轨

- 我方战斗简卡、队友摘要、场景轨、最近公开事件。
- 六根不在交锋小卡常驻显示。
- 危机与解密作为同一“场景轨”系统的不同类型，但不混淆各自语义。

### 中央交锋台

- 抽象表达我方/敌方/中立方、目标线、距离、纠缠、响应和动景。
- 不设计地图、格子、Token 路径或战棋移动。
- 目标线是规则记录，不是装饰；支持一对多的数据结构。
- 选中单位后右侧显示其玩家可见或 DM 完整信息。

### 宣言工作台

- 行动卡手牌、选中卡详情、目标、距离与宣言校验使用同一份草稿状态。
- 右栏、气骰区和底栏不得各自保留独立确认入口。

### 气骰七区工作台

- 气海与临气区是可选气骰源。
- 锁气、阴槽、阳槽是当前宣言的配置和结果。
- 气池和息库是资源去向与待回收状态。
- 每枚骰显示来源、气性、骰阶、当前点数、所在区域的可发现摘要。
- 核心操作不被临气/息库详情展开或错误提示挤出可见区。
- 新场景气池骰通过 3D 投掷遮罩层整体入海，结果按骰阶、气性、点数稳定排序。

### 右侧情境栏

- 玩家：目标公开信息、响应入口与当前落果预览。
- DM：隐藏目标、行为倾向、响应挂载、退场条件、手动覆盖和广播。
- DM 手动覆盖必须生成日志。

### 底部命令条

- 合并自然语言提示、校验失败原因和当前时点操作。
- 每个时点只有一个明确主操作，不复制右侧按钮。

## 5. 权威状态与功能要求

### 单一宣言草稿

`DeclarationDraft` 是选中招式、选中目标、阴槽骰、阳槽骰和校验结果的唯一真实源。

必须保证：

- 战场点击与目标选择器修改同一 `targetId`。
- 招式切换后及时重新校验，行动者切换/落果后清空草稿。
- 一枚骰最多存在于一个槽中。
- 普通阴骰只能进阴槽，阳骰只能进阳槽，原始骰可二选一。
- 宣言确认只调用一次规则引擎。

### 投骰功能

- 投骰请求在确认前不修改战斗状态。
- 确认结果时一次性完成“进入场景 + 气池骰入海 + 事件日志”。
- 取消投骰不保留任何状态变化。
- 投骰结果清晰可读，并在演出后自动归位排序。

### 卡牌与操作

- 卡面常驻：名称、类型/式位、对象/距离、最低投入、基础效果。
- 详情：装备许可、势条件、四类槽值触发、风险、资源去向、响应挂载。
- 不可用卡可见但置灰，必须显示来自规则校验的不可用原因。
- 调息和返照使用与招式一致的选中/确认流程。

### 交锋台与目标线

- DOM 角色卡与 SVG 线必须共享同一容器坐标系。
- 目标线显示行动方、承受方、距离、招式与合法性。
- 落果后依事件更新卡面气血、状态、势与退场状态。

## 6. 验收标准

1. 1366×768 与 1920×1080 一屏内可完成“选招 → 选目标 → 配骰 → 宣言”，无页面级滚动。
2. 开发调试面板默认关闭且可真正关闭。
3. 七个气骰区域均有清晰名称和状态，不再藏在“详情”中。
4. 只存在一个“确认宣言”主操作。
5. 新场景点击投骰会打开 3D 投骰，取消无变化，确认后气骰入海。
6. 切换招式/行动者不会遗留旧槽位气骰。
7. 截击、成招、应招、落果的时点只显示合法操作。
8. 玩家不能看见 DM 隐藏字段；DM 手动修改均写入日志。
9. 气骰数值、气性、骰阶、来源与去向可追溯。
10. 现有规则引擎与 UI 逻辑测试全部通过，新增单一草稿和投骰路径有回归测试。

## 7. 不在本轮自由扩张的内容

- 不自创规则术语。
- 不将交锋台改成格子战棋或地图。
- 不让 UI 直接修改规则结果。
- 不为动画复制第二套战斗状态。
- 不因历史 Godot 文档而放弃当前已接入规则引擎的 React 成果。
