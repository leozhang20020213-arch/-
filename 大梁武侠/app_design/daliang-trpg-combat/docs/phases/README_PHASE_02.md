# 阶段 2：玩家情景双模式工作区

日期：2026-07-15

前置提交：`767a4b24 feat: establish dual-mode runtime and move usages`

## 阶段目标

依照 2026-07-15 Codex 专用任务书，将玩家情景页面从战斗交锋壳中彻底拆出，建立：

- 默认无强制队列的自由情景；
- 只在追逐、潜入、争夺等需要时出现轻量序列的结构化情景；
- 六类行为、情景招式卡、目标、述意草稿与广播范围组成的玩家输入链；
- 文字补充保持可选，不阻塞已经明确用法与目标的结构化行动；
- 单人规则主持与真人 DM 共用的权威 `SceneActionRequest`。

## 已实现

### 独立玩家情景桌面

新增 `PlayerSceneWorkspace`，不再复用：

- `CombatShell`；
- 战斗敌我阵列；
- 敌方气血与战斗目标线；
- 截击/应招额度；
- 完整阴阳配气台；
- 战斗轮阶段操作条。

新桌面固定为：

- 顶部 58—64px：地点、情景模式、资料抽屉与 Windows 控制；
- 中央：场景画布、公开人物/物件/环境立牌、场景轨与事实令牌；
- 右侧 300—324px：可折叠公开情报与最近裁定；
- 底部 224—282px：行为分类、情景招式卡、述意编辑器、广播范围和紧凑气海摘要。

1920×1080 与 1366×768 均不使用页面级滚动。

### 自由情景与结构化情景

- 新故事整体投骰后进入 `SCENE_FREE`，不建立行动队列。
- `SCENE_STRUCTURED` 仅显示情景行动者、当前角色、已行动状态与情景轮次。
- 结构化序列读取 `runtime.scene.sequence`，不会误读或创建战斗 encounter。
- 情景转战斗由真人 DM 决定；单机时由规则型自动 DM 根据结构化条件推进。切换会保留气骰、状态、对象和轨道。
- 自由情景裁定保持 `phase=scene`；结构化情景才进入相应序列时点。

### 六类行为与情景用法

新增六类稳定入口：

1. 查探；
2. 交涉；
3. 潜入；
4. 追逐；
5. 整备；
6. 江湖事务。

新增第一批 12 个情景用法。每个用法具有：

- `MoveUsage` 使用域与合法模式；
- 对应的权威旧行动入口；
- 目标规则；
- 最低气要求；
- 基础效果短句；
- 风险标签；
- 资源去向。

卡牌只显示名称、短效果、最低气和风险；目标、完整说明与公开信息通过画布高亮、悬停浮框和右侧检查器展开。

### 玩家述意与广播

行动提交固定为：

`行为分类 → 情景用法 → 公开目标 → 可选文本述意 → 广播范围 → 发送`

- 已选择合法用法与目标时，文本述意可以为空；纯自由叙事才要求文本。
- 切换行为会重算合法目标，旧目标不合法时自动清空。
- 述意草稿切换卡牌时保持，可由玩家主动撤回。
- 默认全员广播。
- 房主可设置是否允许玩家发送“仅 DM”述意。
- `SceneActionRequest` 使用 `sourceId` 与 `audience`；不包含音频或转写来源字段。
- DM 私密请求、自动裁定和 DM 裁定均不进入公开日志。

### 新场景整体投骰

应用层新故事进入情景时改用 `startNewScene(..., "SCENE_FREE")`：

- 规则层先确定权威骰面，Three.js 只负责表现；
- 自由情景不再错误确认一套战斗/结构化先后；
- 已有结构化情景兼容路径仍可确认自己的情景序列。
