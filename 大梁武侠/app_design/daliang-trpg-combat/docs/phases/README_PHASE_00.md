## 结构审计

| 区域 | 现状 | 风险 | 阶段迁移 |
|---|---|---|---|
| `src/ui/App.tsx` | 约 145 KB，集中路由、状态、玩家/DM 页面、抽屉和动作 | 修改任一模式容易影响全部页面 | 阶段 1 拆工作区与控制器；后续逐页迁移 |
| `src/combat/combatEngine.ts` | 约 85 KB，同时处理情景切换和战斗事务 | 情景/战斗轮次、响应额度和存档边界混杂 | 阶段 1 引入会话壳与独立 encounter |
| `CombatState.encounterMode` | 仅 `scene/combat` 二值 | 无法表达自由情景与结构化情景 | 改为三态 `SCENE_FREE/SCENE_STRUCTURED/COMBAT` |
| `CombatState.round` | 情景和战斗共用 | 与新任务书“战斗先后独立”冲突 | 拆为 `sceneSequence` 与 `combatEncounter.round` |
| `Actor.responseQuotaUsed` | 截击、第三方护人、自保应招共用 | 玩家无法判断消耗的是哪种资格 | 拆为主动响应额度与目标自保额度 |
| `Move` | 定义和单一用法合并 | 同招式无法在情景/战斗拥有不同效果 | 建立 `MoveDefinition + MoveUsage` |
| 响应 UI | 已嵌入交锋画面，但仍是右侧浅色独立工作台 | 视觉和交互仍近似弹窗 | 阶段 3 迁入原手牌与气骰台 |
| 人物/背包 | 右侧窄浅色抽屉 | 不满足大型暗黑式覆盖页 | 阶段 4 替换 |
| DM | 有运行桌面和手动覆盖 | 缺少创作工作台与团包校验 | 阶段 6 新增独立 `DMCreatorStudio` |
| 默认团包 | `桥陵镇雨夜失镖/旧堤仓` 硬编码在 `seed.ts` | 与新手团包要求冲突 | 迁到 legacy fixture；阶段 9 换为《白蘋渡失匣》 |
| 美术 | 40 个图标存在 PNG/WEBP 多规格，共 160 文件 | 超出“首批 24 图标”但可作为旧资源，不应继续无序扩张 | 阶段 8 用 manifest 白名单接入 |

## 视觉基线结论

- 玩家情景页仍是“战斗交锋台换标题”：存在敌我阵列、统一轮次与战斗式人物席位；不符合自由情景默认形态。
- 响应阶段虽未遮住整个屏幕，但右侧浅纸工作台脱离原手牌和气域，仍形成第二操作中心。
- 背包是窄浅色信息抽屉，缺少人物立绘、装备环、网格背包、负重与美术资源位。
- DM 运行桌面已经明显区别于玩家桌面，应保留；当前问题是缺少创作工作台，而不是重做运行桌面。
- 主交锋台的卡牌、目标线、七区气域和稳定人物席位继续作为战斗模式基础。
