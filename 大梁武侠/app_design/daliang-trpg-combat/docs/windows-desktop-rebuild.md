# Windows 桌面重构实现说明

## 运行边界

- 只发布 Windows x64 桌面应用；React 是渲染层，不提供网站部署、移动端或 SEO。
- Electron 主窗口默认 `1600×900`，最小 `1280×720`，支持窗口化、最大化、还原、最小化、关闭和 `F11` 全屏。
- 渲染器开启 `contextIsolation` 与沙箱，关闭 Node 权限；preload 只暴露五个窗口动作和只读窗口状态。
- 拒绝新窗口、外部导航和 webview；正式构建关闭 DevTools。
- 存档由 Chromium 隔离存储保存在 Electron 的 Windows 应用数据目录中，旧版存档会补齐情景、席位和自动 DM 字段。

## 身份与流程

- 玩家入口：继续单人故事、新开单人故事、加入房间。新故事会清空旧交锋运行态，再进入人物选择。
- “继续”入口读取已保存的 `gameMode`，情景存档返回情景桌面，交锋存档返回原轮次交锋台。
- 主持入口：继续主持、创建房间、管理团包。真人 DM 桌面拥有隐藏对象、危机阈值、解密层、广播和手动覆盖；玩家不可见。
- 单人自动 DM 是确定性规则核心：观察、交涉、搜查、移步、取物和使用物品均校验公开目标与互动入口，再修改解密、危机、许可和资源。
- 可选 AI 仅润色已通过的裁定；2.5 秒超时、断网、非法输出或空端点都会立即保留本地规则叙述，AI 不直接写状态。
- 交锋自动 DM 处理敌方选招、目标、配骰、截击、应招、落果和轮末；受招目标是玩家时停在玩家响应工作台。
- 真人房间的玩家行动只生成待裁定请求，不预先修改权威状态；DM 可批准、修改或驳回，并通过同机双窗口或局域网同步公开结果。
