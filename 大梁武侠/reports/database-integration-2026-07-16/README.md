# 《大梁武侠》规则与数据库接入审计报告

日期：2026-07-16
程序：`app_design/daliang-trpg-combat`（React + Electron Windows）

## 1. 本次采用的权威顺序

出现冲突时按以下顺序处理：

1. 2026-07-15 已冻结口径：交锋轮、调息、返照、主动响应与自保应招额度。
2. 2026-07-16 规则文字库：条目正文、资源说明、DM投放说明和资料索引。
3. 2026-06-20 回填修订规则包：六根、内功、表属性、气骰、装备位、状态与数据库边界等稳定基础。
4. 程序原有手写小样：只保留为已经测试的可执行回归基线，不反向覆盖新规则正文。

因此，7月16日工作簿中的1004条内容没有被直接视为可执行脚本。文字资料与权威状态修改被明确分离。

## 3. 自动审计结论

生成的程序目录分为三级：

| 状态 | 数量 | 程序处理 |
|---|---:|---|
| 资料可用（REFERENCE） | 831 | 可检索、可阅读、可由DM引用；仍不直接执行 |
| 需要复核（REVIEW_REQUIRED） | 133 | 可查看问题，但禁止进入自动DM和权威结算 |
| 暂不接入（QUARANTINED） | 40 | 关键参数丢失，禁止加入团包 |

主要风险如下：

1. **133条恒触发门槛。** 例如`MV-FP-14 崩山三叠`的宣言已经要求合值至少30，但合值附加触发只要求26；`SM-01-01 听痕辨路`使用条件要求合值至少11，附加触发却只要求10。若按当前文字运行，附加触发在合法成招后恒定发生。程序没有擅自修改门槛，而是统一阻断自动接入。
2. **45条极高气骰投入。** 最低投入达到10或12枚，明显超过当前教学角色6枚常规气骰规模。它们可能属于高阶人物，但必须先建立阶段、总气骰规模和获得条件，不能混入新手池。
3. **45条高基础伤害，其中15条达到18点。** 当前样例敌人气血多为8—14点，18点固定基础落果可直接击倒完整样例敌人。程序保留资料，不自动削弱，也不投放给教学角色。
4. **106条原始结构化字面量。** 谱本、禁功等条目把参数写成Python字典文字。玩家显示层已本地化常见结构，但这些条目仍需正式Schema后才能执行。
5. **40条坐骑/载具参数丢失。** “维护成本”在源工作簿中已经变成`[object Object]`，无法从文字逆推出原值。全部坐骑条目已隔离，等待源数据重新导出。
6. **开发令牌直出。** `TURN_READY`、`SCENE_ACTION`、`regular_qi`等令牌大量存在。运行时资料库已统一转换为中文显示，原始令牌不再暴露给玩家。
7. **场景轨绑定风险。** “危机+1”“解密+1”只有在绑定具体场景轨后才可写入权威状态；程序不会把泛称危机自动写到任意轨道。

机器可读明细见`catalog-audit.json`。

## 4. 程序接入方式

### 完整文字目录

生成静态版本快照：

- `public/data/rules/rule-text-catalog-v2026-07-16.json`
- `public/data/rules/catalog-manifest.json`

目录包含来源工作表和行号、条目分类、玩家文本、DM文本、规范化字段、风险状态和问题清单。它通过运行时延迟请求载入，不进入主JavaScript包；断网时仍从Electron本地安装目录读取。

### 可执行数据隔离

完整文字库统一标记为`CATALOG_ONLY`。现有规则引擎继续使用已经有测试覆盖的`MoveDefinition / MoveUsage`与手写样例，不根据名称猜测效果，也不把同名的新旧条目强行合并。

DM创作台可以把`REFERENCE`条目作为场景元素的`ruleReferenceIds`引用。引用本身只提供说明，不修改权威状态；真正执行仍须绑定明确的结构化用法。`REVIEW_REQUIRED`与`QUARANTINED`条目不会出现在可选资源中。

### 首批可执行资源

样例背包对已有资源进行了明确映射：

- 环首刀 → `EQ-W-001`。
- 厚布短褂 → `EQ-AU-001`。
- 火折 → `EQ-T-001`。
- 金疮药 → `MED-001`。

金疮药现在真实结算固定`气血+4`；同一场景第二次使用写入`药性冲突`，并记录场景内物品事务。装备属性和即时治疗字段已分开，避免旧`attrBonus.气血`同时表示永久属性与治疗的语义Bug。

## 5. 已修复的冲突与Bug

- 修正旧规则目录中“调息重投”的错误说明：调息支付息引、取回规则允许的常规骰并保持原点数。
- 修正旧规则目录中“返照不重投”的错误说明：返照每轮一次，取最低阶本命骰重投，且不消耗正式出手。
- 金疮药不再只是无效果的说明文字。
- 药物重复使用按场景记录，不会把旧场景使用次数错误带入新场景。
- DM创作台不再显示英文`container`，并补齐区域、队友、容器、文书等场景元素。
- 团包Schema支持版本化规则资料引用，并检查重复和非法引用标识。
- 玩家资料库不显示DM与开发字段；DM身份可以查看DM裁定和开发边界。
- 原始开发令牌、双句号和已知结构化字面量在玩家显示层规范化。

## 6. UI升级

- 资料库改成暗木案桌式双栏档案馆，而非浅色卡片墙。
- 顶部直接显示总条目、资料可用、需要复核、暂不接入四个数字。
- 支持类别、审校状态和全文搜索。
- 左侧为紧凑条目索引，右侧显示玩家规则、字段说明、DM裁定与接入限制。
- 当前团包可执行数据与完整文字库分为两个页签，避免玩家误以为1004条都已能使用。

- 背包详情显示规则资料ID、固定效果和重复使用后果。
- 1366×768下保持单屏桌面，长列表和详情只在各自内部滚动。

## 8. 未自动修改的规则问题

以下问题必须由规则作者确认，程序没有擅自发明答案：

1. 133条恒触发合值门槛究竟是“附加效果本来就应随成功自动发生”，还是批量生成错误。
2. 10—12枚最低投入与18点基础伤害对应的角色阶段、总气骰规模和敌人气血基准。
3. 40条坐骑/载具遗失的维护成本原始参数。
4. 禁功与高阶内功字典参数的正式字段、循环限制和退出条件。
5. 每条“危机/解密”效果应绑定的具体场景轨ID。
6. 新文字库同名条目与旧可执行样例效果差异很大，不能只按名字迁移；需要逐条制作`MoveUsage`适配器和回归用例。

这些问题解决前，当前的“资料可见、异常隔离、可执行小样稳定”方案比批量自动导入更安全。
