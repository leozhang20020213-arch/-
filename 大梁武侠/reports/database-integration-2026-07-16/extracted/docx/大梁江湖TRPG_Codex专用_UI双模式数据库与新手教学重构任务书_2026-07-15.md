## 0. Codex 执行总令

本次不是推翻现有 React + Electron 工程，也不是另起一个静态原型。当前版本已经具备运行、测试、打包和交互闭环，重构应当保留可用底层，替换错误的信息架构、模式边界、抽屉布局、响应表现、示例剧情与数据组织。

### 0.1 必须完成的九项结果

情景模式与战斗模式使用不同的工作区、不同的流程控制器和不同的招式可用域；两者只共享角色、气骰、资源、场景对象和日志，不再只是同一页面换一个标题。

招式数据库增加明确的使用域和用法变体：仅情景、仅战斗、两者通用、模式转换、DM专用；界面只显示当前模式、时点、目标、距离、装备和势都合法的用法。

人物与背包不再使用窄白色右抽屉；改为接近暗黑类游戏的人物纸娃娃、装备槽、背包格与物品详情的大型覆盖界面，并为立绘、装备图标、物品图、背景纹理预留固定资源位。

截击与应招不得弹出独立模态窗口。响应时点到来时，原有气骰台和招式区进入响应态，合法响应用法高亮、抬升并显示可配骰区域，棋盘保持可见。

DM端增加剧情结构、场景、战斗、NPC、动景、目标线、危机／解密、触发器和广播内容的编辑空间，允许主持人自己制作团包，而不是只能运行预制样例。

情景模式增加行为分类、可用法门／外功筛选、文本与语音输入、提交给DM、全员广播、DM映射规则入口的完整链路。

日志按玩家能读懂的行动句子组织，并保留可折叠的技术详情；不再把大量底层枚举和单个气骰移动作为主日志。

统一主界面、抽屉、人物、背包、卡牌、按钮、图标、动效、颜色与字体。只接入一小批核心图标与现有美术资源，先完成映照体系，不在本阶段追求全量美术。

取消当前默认样式剧情，将其移出玩家入口，替换为结构清楚、可覆盖主要系统的新手教学关卡《白蘋渡失匣》。

### 0.2 明确禁止

禁止继续在现有同一块中央空舞台上叠加更多文字和按钮来假装区分情景／战斗。

禁止新增截击弹窗、应招弹窗、调息弹窗。调息可使用底部展开面板，但不遮挡主棋盘，不形成页面中心模态框。

禁止把旧样例剧情继续硬编码在组件、store或测试夹具中。旧内容可归档到 fixtures/legacy，但不得作为默认团包。

禁止把完整数据库做成同名换皮、数值平移或大量“招式一、招式二”。所有条目必须通过重复度、字段完整性、使用域和强度审计。

禁止用纯白后台表单作为DM创作工作台和人物／背包界面；编辑器可以清楚，但必须与游戏总美术体系一致。

禁止因动画速度或跳过动画而改变随机结果、响应时点、日志内容或网络同步。

### 0.3 每阶段提交纪律

先读取现有 README、package.json、状态管理、数据目录、测试目录与远端 Git 配置，写出本阶段改造范围。

一次只处理一个阶段，不同时重写全部状态机与全部美术。

阶段结束必须补充或新建 README_PHASE_XX.md，列出已改文件、规则口径、测试命令、截图名称、遗留问题和下一阶段入口。

运行自动测试、数据校验、Electron构建与关键交互巡检；失败不得用“暂时跳过测试”交付。

提交到现有 Git 仓库并推送已配置的远端 origin；提交信息包含阶段号和模块名。

## 11. 动画速度、反馈与可调设置

### 11.1 动画速度档位

玩家可以设置本地动画速度；DM可在房间中设置“建议速度”和是否同步等待关键演出。网络逻辑以事务完成为准，不能等待某个客户端动画帧。

### 11.2 统一动效原则

同一时点只有一个强焦点。金色只用于当前主要操作；阴、阳、应招、危险各用自己的功能色。

卡牌悬停上浮16—24px；选中后进入动作槽，不持续放大遮挡。

响应卡只短脉冲一次；合法目标使用轮廓与轻呼吸，不全部发光。

气骰在气海、锁气、槽位、息库间有明确路径；速度改变不改变路径和日志。

伤害、护体、状态、势和场景轨变化先显示前后值，再播放简短反馈。

所有动效提供减少动态效果选项；不得用震屏表现普通点击。

## 12. 统一美术系统与资源映照表

### 12.1 统一风格

整体采用“深色木漆桌面＋旧纸／皮革内层＋青铜和暗金结构件”的武侠桌游风格。主桌面、人物、背包、DM运行台和创作工作台必须属于同一套设计语言，不能主界面黑金、抽屉纯白、设置页网页卡片。

### 12.2 首批美术接入限制

### 12.4 资源包目录
