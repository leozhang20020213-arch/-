# 《大梁武侠》正常游玩流程升级与审查记录

日期：2026-07-16
范围：React + Electron Windows 桌面版正常故事、玩家交锋、自动角色、真人 DM 和发布检查。

## 本轮结论

本轮不再把《白蘋渡失匣》教学关卡当成唯一可运行内容，而是建立了可重复使用的正式团包运行框架，并加入非教学故事《雾岭盐引》。玩家可从首页选择不同主角进入正常故事，依次完成自由情景、结构化护送、对质、战斗和结局；真人 DM 也可创建该团包的房间，运行场景、接管敌人、处理响应并手动收束。

规则引擎继续作为唯一权威层。团包只组合已登记的人物、招式、事件、距离和奖励，不在 UI 或剧情文件中另写一套战斗计算。

## 主要整改

### 正常故事与团包运行

- 新增团包注册表，在正常故事和教学故事之间明确分流。
- 新增《雾岭盐引》五个可运行场景：雁回驿调查、芦岭护送、盐场对质、盐场夺账、县廨封卷。
- 提供四名可选主角和三种结局；主角会替换团包中的作者占位角色，不会同时生成重复玩家角色。
- 场景事件、轨道、公开/隐藏元素、许可、资源和结局全部经过团包结构校验。
- 正常故事中的敌人使用独立目标与策略，不再继承教学关卡的药匣、渡船等叙事目标。
- 旧存档迁移时按稳定 ID 合并人物，并补入新数据，不覆盖玩家已经形成的权威状态。

### 情景到战斗

- 自由情景可执行调查、交涉、取物、用物等真实事件，并驱动轨道和场景切换。
- 结构化情景使用行动序列，自动角色每次只推进一个权威步骤，避免一键跳完整轮次。
- 情景进入战斗保留原气骰、息库、临气与状态；只有本场没有骰面的新增角色进行补投。
- 真人 DM 从非相邻情景手动升级战斗时，系统会落到团包中已审核的战斗场景，不再生成空战场。
- 终局场景明确禁止再次升级战斗。

### 交锋轮与自动角色

- 战斗手牌只展示具有 `COMBAT` 用法的招式；情景法门不会混入战斗手牌。
- 行动序列严格使用当前场景的参战者，人物注册表中的其他预设角色不会混入顺序或骰池。
- 顶部显示权威顺位而不是容易误解或泄露的内部先后分数。
- 修正响应机会判断：由防守者的合法响应挂载与响应额度决定，不再被进攻招式的错误标记抑制。
- 自动角色在玩家成为目标或存在护人机会时暂停；无合法行动时使用移动、调势、调息、返照或安全放弃，避免死循环。
- “出手结束”与真正“轮末”分离。每名角色完成后只进入下一行动者；所有角色完成后才结算轮末维护。
- 调息支付息引、按规则从息库回收并保持点数，且消耗正式出手；同一角色不能连续无限回气。

### 真人 DM

- DM 情景台只显示当前场景演员，不把全部角色数据库铺到运行台。
- 敌方隐藏目标来自当前团包的角色档案。
- 手动接管必须完成招式、目标、气骰和距离合法性检查；不合法时确认按钮保持禁用并显示原因。
- 截击与应招继续在原交锋桌面内处理，没有恢复独立响应弹窗。
- DM 可在战斗中宣布撤退、投降等收束，完成不可逆确认后进入团包指定的后续场景。

### UI 与发布

- 首页将“正常故事”和“新手教学”拆成不同入口。
- 交锋、情景、结局和 DM 页面统一读取当前团包名称、场景和演员，不再常驻教学文本。
- 3D 骰盘保持按需加载，战斗阶段只为当前参战者补骰。
- Windows 构建显式使用 `大梁武侠.exe`，保留隔离 preload 与应用数据目录存档。
- 在含中文的工作区中，默认 Electron 下载包的目录重命名会触发 Windows `EPERM`；构建配置改为复用项目已安装的 Electron 分发目录，绕开该环境问题，并实际生成可运行的 `release/win-unpacked/大梁武侠.exe`。

## 实际游玩审查

### 玩家流程

实际操作完成：

1. 首页进入正常故事并选择唐禾。
2. 新场景整体投骰。
3. 雁回驿调查取得证据并进入结构化护送。
4. 芦岭护送沿用原骰面，没有重投。
5. 盐场对质转入五人战斗。
6. 选招、选目标、投入气骰并宣言。
7. 敌人自动行动，玩家处理响应时点。
8. 打开人物、背包等抽屉后，选牌、目标和投入状态不丢失。
9. 完成一次真实调息：息引进入息库、回收骰保持原点数、正式出手被消耗，无法同轮重复。

### 真人 DM 流程

实际操作完成：

1. 创建《雾岭盐引》房间并开始场景。
2. 进入“盐场夺账”五人交锋。
3. 接管敌人并选择招式、目标和气骰。
4. 在距离未知时确认被禁止；DM 设置合法近身距离后确认恢复。
5. 在原桌面处理截击，随后推进下一行动者，轮次没有被错误增加。
6. 宣布敌方撤退，经过不可逆确认后进入“县廨封卷”。
7. 玩家侧不显示敌方完整骰子、隐藏目标或 DM 备注。

浏览器控制台：错误 0，警告 0。

## 仍需后续扩充但不阻塞正常流程的事项

- 当前正式团包只有一部；注册表和校验接口已经支持继续加入团包。
- 招式与敌人仍以本轮已审查的权威数据为主，没有凭空批量补写规则书未冻结的数值。
- Vite 对主包和 Three.js 骰子包给出大于 500 kB 的性能提示；骰盘已经懒加载，后续可继续拆分资料库和 DM 编辑器，但该提示不影响功能或 Windows 启动。
- 当前交付验证的是 Windows x64 目录版；正式安装器、签名和杀毒软件兼容性仍应在发布环境单独验收。
