# 《大梁武侠》整体游戏、开团与数据库大审查

审查日期：2026-07-16

审查对象：React 19 + Electron 43 Windows x64 桌面版
结论：**核心规则闭环、开卡、自由情景、结构化追逐、战斗、自动角色和 DM 手动接管已形成可运行样例；当前为“可继续内测”，尚不建议宣称完整数据库与多人发布版完成。**

## 1. 规则权威与审查方法

本轮按以下优先级处理冲突：

1. `大梁武侠_规则文字库详设包_2026年7月16日`：文字库、分类、来源与数值风险审查依据。
2. `大梁江湖TRPG_内测第一版文件包_回填修订_2026年6月20日`：气骰、距离、势、行动时点、截击、成招、应招、落果、调息与返照的基础规则依据。
3. 2026-07-15 UI、双模式数据库与新手教学任务书：情景/战斗模式、玩家/DM职责和 Windows UI 冻结口径。
4. 现有权威引擎测试：仅用于确认兼容性，不能反向覆盖新规则书。

审查使用了文档抽取、工作簿逐表检查、规则目录验证、Playwright 真实点击、Windows Electron 实机控制、规则模拟和生产打包。不是只看截图，也不是只跑单元测试。

## 2. 本轮实际覆盖

- 文档与数据库：7月16日文字库 1004 条、旧大小样库 40 张表、旧招式修订样本 6 张表。
- 自动流程：20 次完整教学情景路径、30 次三轮自动战斗、100 组房间席位组合。
- 真实玩家操作：首页、五步开卡、自由情景三类行动、三轮结构化追逐、船棚对峙、情景转战斗、人物/六根/背包/招式抽屉。
- 真实 DM 操作：创建房间、席位准备、隐藏牌匣、日志、广播、自动建议、手动接管、截击、应招与落果确认。
- Windows：生产构建、x64 目录包、打包后 `大梁武侠.exe` 冷启动和继续存档。
- 分辨率：本轮新增 1366×768 与 1920×1080 核心桌面截图；完整 100%/125%/150% 与窗口状态截图沿用并复核现有 52 张 Electron 验收包。

## 3. 数据库质量结论

### 7月16日规则文字库

| 状态 | 条数 | 程序处理 |
| --- | ---: | --- |
| REFERENCE | 831 | 可作为资料库文字与人工映射来源；仍是 `CATALOG_ONLY`，不能直接执行 |
| REVIEW_REQUIRED | 133 | 隔离；必须人工复核门槛、总触发或数值后才能映射 |
| QUARANTINED | 40 | 隔离；发现未序列化对象，不进入玩家流程和自动 DM |
| 合计 | 1004 | ID 唯一，分类总量与清单一致 |

按类别：外功 240、内功 120、情景法门 120、装备 180、药物 60、状态 64、手册 60、坐骑 40、文书 120。

主要风险信号：

| 风险 | 命中条数/次数 | 判断 |
| --- | ---: | --- |
| 总触发可能常驻 | 133 | 高风险，不能自动执行 |
| 极高气骰需求 | 45 | 高风险，可能造成不可用卡或构筑锁死 |
| 高基础伤害 | 30 | 高风险，需要与气血区间、护体和轮次长度联调 |
| 致命基础伤害 | 15 | 最高风险，禁止直接进入教学或自动 DM |
| 高治疗量 | 5 | 中高风险，可能抹平伤势与药性代价 |
| 未序列化对象 | 40 | 数据错误，已隔离 |
| 原始结构令牌 | 106 | 中风险，必须经字段解析器转换，不能直接显示给玩家 |

程序没有把这 1004 条文字记录伪装成可执行招式。当前教学团包和角色只引用通过审校的目录条目，真正修改状态的仍是人工映射后的 `MoveDefinition` / `MoveUsage`、物品和状态定义。

### 旧工作簿

- `01_大小样库.xlsx`：570 个数据行；跨表出现 50 个重复 ID。多数是主表与明细表的合法外键复用，不能简单删除，但导入器必须按“表名 + 主键职责”区分实体定义和明细引用。
- `02_招式库小样本_响应挂载与势前置修订.xlsx`：63 个有效数据行，另有 1131 个格式化空白行。导入时必须按有效行裁剪，否则会制造巨大空记录和错误统计。
- 新文字库工作簿：1015 个数据行（含说明/统计），40 个对象字面量错误与程序目录中的 40 条隔离记录一致，审计链闭合。

## 4. 开卡环节

现已形成五步开卡：

1. 选择出身：展示定位、难度、默认姓名与玩法倾向。
2. 分配六根：合计 24 点，每根 1—6，实时显示剩余点数与雷达图。
3. 选择内功：展示读根、占窍、取气结构和上手提示。
4. 选择初始武艺：3—5 条，至少一条外功、一条情景法门和一项截击/应招挂载。
5. 确认人物：姓名、头像、本地图片、人物背景、开局关系、六根、武艺与 5—8 枚初始气骰总览。

创建后的自定义主角会替换模板主角进入既有抽象距离图，不会产生“新人物无距离关系、所有招式都不合法”的死档。当前尚缺的是把教学团包定义的四名快速角色直接接入开卡选择；它们目前只完成结构定义和校验。

## 5. 新手教学关卡：《白蘋渡失匣》

### 场景流程

| 步骤 | 模式 | 教学目标 | 关键验收 |
| --- | --- | --- | --- |
| T0 | 开场 | 认识角色、目标与气骰 | 冷启动不直接跳页 |
| T1 | 自由情景 | 观察西栈封门 | 公开信息不消耗正式出手 |
| T2 | 自由情景 | 搜证、取封绳、闭合 4 条线索 | 危机、解密、许可与资源真实变化 |
| T3 | 结构化情景 | 三轮追上抱匣人 | 只允许已编排三人入队；不重投气骰 |
| T4 | 自由情景 | 旧船棚交涉或取匣 | 可非战斗解决，也可确认进入交锋 |
| T5 | 战斗 | 选招、目标、阴阳配气与宣言 | 情景资源和气骰沿用 |
| T6 | 战斗响应 | 截击、成招、应招和受击 | 玩家响应时自动流程暂停 |
| T7 | 收束 | 调息、返照、撤退/投降/取匣 | 四种结局结构可校验 |

四种结局：完匣归还、揭出调包链、带伤夺回、失匣追踪。关卡数据、场景投影、触发条件和结局引用已经完成；屏幕上的逐步教学遮罩、跳过状态和 T0—T7 自动完成判定尚未接入，因此“关卡可玩”已达到，“完整新手引导产品化”尚未达到。

## 6. 真实游玩与开团结果

### 玩家流程

- 自由情景的观察、搜证、取物可以真实改变解密、危机、许可和资源。
- 第三次搜证后自动进入结构化追逐；行动序列为沈青、魏长兴、黑衣脚夫，不再混入未来战斗敌人。
- 三轮追逐完成后进入旧船棚对峙；取匣后进入战斗，不重新投骰。
- 战斗桌面在 1366×768 一屏保留行动顺序、抽象战场、七区气域和横向手牌。
- 抽屉打开不丢失选牌、目标、气骰和响应状态。
- 玩家不能操作 DM 隐藏信息；响应牌按真实 `responses` 数据分类，不再把普通招式误列为截击/应招。

### 自动角色

- 30 次三轮战斗均在 180 步上限内推进，没有重复状态死循环。
- 玩家成为响应目标时暂停；玩家额度耗尽后不会反复弹回等待。
- 无合法招式时可回退到移动、调势、调息、返照或放弃出手。
- 结构化情景角色只做情景序列推进，不再调用战斗 AI 生成隐藏响应窗口。

### 真人 DM

- 新建房间现在清空“房间槽”而不是继承单人剧情。
- DM 可查看并揭示隐藏牌、广播、记录裁定、接管敌人、处理内嵌截击和应招、确认落果。
- “代为应招”会搜索真实合法响应和气骰组合，不再固定拿第一张牌/第一枚骰而失败。
- 100 组席位组合验证了角色冲突、未分配、未准备和连接状态的开场阻断。
- 内嵌 LAN 房主测试通过了私密请求隔离和权威快照；最新版本尚未再次完成两台独立 Windows 进程的完整真人联机实测，因此不能把多人网络列为最终发布通过。

## 7. 本轮发现并修复的问题

1. 自由情景误把所有 NPC 自动轮转。
2. 情景切换后保留了上一场景的选牌和目标。
3. 结构化追逐把全部战斗角色追加进行动序列。
4. 结构化情景调用战斗 AI，生成玩家看不到的截击窗口并卡死。
5. DM 新建房间继承旧单人存档、轨道、骰子和隐藏信息。
6. 单人故事与真人 DM 房间共用同一权威存档槽；现已拆为 `combat-solo` 与 `combat-room`，并提供旧 `combat` 槽一次性迁移。
7. DM 代为应招选错响应牌和骰子，明明存在合法组合却失败。
8. 装备可重复叠加属性/气骰，同类装备可同时标记为已装备。
9. 旧存档的重复装备标志与权威装备槽冲突。
10. 招式抽屉的截击/应招筛选使用 `hasIntercept` 猜测，导致普通招式混入。
11. 正式背包暴露“打落短兵”等测试夹具；测试数据已移出生产种子。
12. 工作簿审计把总行数当有效行数；现已分离有效行、格式化空白行和错误单元格。

## 10. 发布判断

本轮可以作为下一次内部试玩基线：单机开卡、教学场景、结构化追逐、战斗和 DM 手动裁定已能运行，且关键死锁、串档、装备叠加和响应选择错误已修复。

正式对外发布仍需先完成 A-02 与 A-03；数据库扩展发布需先完成 A-01。任何报告都不应把 831 条 `REFERENCE` 文字记录描述成 831 条已经由规则引擎执行的招式或物品。
